【操作系统原理】 Lecture 8 虚拟存储概念

发表于2025-11-05|更新于2026-07-03|技术学习操作系统原理
|浏览量:

一、虚拟存储的需求背景

1. 存储需求增长

  • 程序规模 vs 存储容量：
    • 应用程序（如大型游戏）规模增长速度远超物理内存容量。
    • 核心矛盾：需要运行比物理内存更大的程序。

2. 存储层次结构

  • 金字塔模型：
    • 顶层：CPU寄存器（最快，容量最小）。
    • 中层：高速缓存、主存（RAM）。
    • 底层：磁盘（最慢，容量最大）。
  • 操作系统抽象：
    • 通过虚拟存储技术，将外存（磁盘）扩展为内存的延伸。

二、核心技术：覆盖与交换

1. 覆盖技术

  • 原理：
    • 按程序逻辑划分模块，将不会同时执行的模块共享同一内存区域。
  • 示例：
    • 模块A（20K）独立占用。
    • 模块B/E/F（50K）共享区域，模块C/D（30K）共享区域。
    • 总内存需求：100K（原需150K）。
  • 不足：
    • 需程序员手动划分模块，增加编程复杂度。
    • 无法自动适应动态内存需求。

2. 交换技术

  • 原理：
    • 将内存中暂时不运行的进程整体换出到外存，释放内存空间。
  • 流程：
    1. 换出：选择等待进程（如P2），写入磁盘。
    2. 换入：需要时再从磁盘加载回内存。
  • 面临问题：
    • 交换区大小：需预留足够磁盘空间。
    • 交换时机：何时触发交换（如内存不足时）。
    • 重定位问题：换入后需放回原地址或动态重定位。

3. 覆盖 vs 交换

技术 优点 缺点
覆盖 减少内存占用，无需OS支持 依赖程序员手动管理
交换 自动管理，支持多进程 整体换入/换出开销大

三、局部性原理

1. 定义

  • 时间局部性：最近访问的数据可能再次被访问（如循环变量）。
  • 空间局部性：相邻地址的数据可能被连续访问（如数组遍历）。

2. 示例分析

  • 场景：二维数组A[1024][1024]按行存储，页面大小4K，物理页数=1。
  • 两种遍历方式：
  • 结论：

    • 方法1每次访问跨页，导致频繁缺页；方法2连续访问同一页，缺页次数显著减少。

      四、虚拟页式存储管理

      1. 核心思想

  • 按需加载：仅将当前需要的页加载到内存，其余页暂存外存。
  • 地址转换流程：
    1. 逻辑地址 → (页号p, 页内偏移o)。
    2. 页表查询：
      • 若页表项有效（P=1），直接获取物理帧号f。
      • 若无效（P=0），触发缺页异常。
    3. 物理地址 = f * 页大小 + o。
      #### 2. 页表项结构（x86）
      | 标志位 | 含义 |
      |————|———————————–|
      | P（驻留位）| 1=页在内存，0=页在外存 |
      | W（可写） | 1=可写，0=只读 |
      | U（用户态）| 1=用户态可访问，0=仅内核可访问 |
      | A（访问位）| 硬件自动置位，记录是否被访问 |
      | D（修改位）| 1=页被修改，需写回外存 |
      #### 3. 示例
  • 逻辑地址16位，物理内存32K，页大小4K：
    • 访问8192（逻辑地址）→ 页号2 → 缺页异常（页不在内存）。
    • 访问32780（逻辑地址）→ 页号8 → 缺页异常（超出物理内存范围）。

五、缺页异常处理

1. 处理流程

  1. 分配空闲页帧：若有空闲物理页，直接分配。
  2. 页面置换：
    • 选择被替换的页q（如LRU算法）。
    • 若q被修改（D=1），写回外存。
  3. 加载新页：
    • 将缺页p从外存加载到物理页帧f。
    • 更新页表项（P=1，帧号=f）。
  4. 重新执行指令：恢复产生缺页的指令。
    #### 2. 外存管理
  • 交换区（Swap Area）：
    • 专门用于存储换出页的磁盘区域。
    • 需高效管理（如位图记录空闲块）。
      #### 3. 性能影响
  • 缺页中断开销：
    • 磁盘I/O延迟远高于内存访问（约10^5倍）。
  • 优化方向：
    • 预取：提前加载可能访问的页。
    • 页置换算法：LRU、Clock等减少缺页率。
