【COMPSCI 320】 Lecture 06 Perrin Numbers: An Algorithm Design Example

发表于2026-10-23|更新于2026-10-23|技术学习COMPSCI 320 Applied Algorithms
|浏览量:

Overview

Perrin Numbers

Perrin numbers are closely related to Fibonacci numbers. \[ P(0) = 3 \\ P(1) = 0 \\ P(2) = 2 \\ P(n) = P(n - 2) + P(n - 3) \]

Initial Observation

The values of \(n\) which evenly divide \(P(n)\) in the above list are exactly 2, 3, 5, 7, 11, and 13.

This list is exactly the list of prime numbers in the range 0..14.

Natural Question

Let \(S\) be the set of all numbers \(n\) such that \(P(n)\) is divisible by \(n\). Is \(S\) the set of all prime numbers?

To find a counter-example to this conjecture, we want to to write a program that outputs all Perrin pseudo-primes from 1 to 1 billion.

Revised Equivalant Problem

We are really interested in whether \(P(n)\) is divisible by \(n\). Let \(P(n, m) = P(n) \mod m\). \[ P(n, m) = (P(n - 2, m) + P(n - 3, m), \mod m) \]

Now compute \(P(n, n)\). Note that \(P(n)\) is divisible by \(n\) \(\iff P(n, n) = 0\).

Brute Force

The first thought is to take the formulas above, and implement them directly using a recursive algorithm.

The problem is that when n starts getting larger, this (first) program takes a very long time to run.

We will describe the running time of the algorithm with a recurrence equation: \[ T(k) = 1, k < 3 \\ T(n) = T(n - 2) + T(n - 3) + c, n > 2 \]

Base. It is obvoius that \(T(n) \geq \frac{1}{2}(1.3)^n\).

Induction. Assume \(T(k) \geq \frac{1}{2}(1.3)^k, k < n\). \[ \begin{align} T(n) \geq& \frac{1}{2}(1.3)^{n - 2} + \frac{1}{2}(1.3)^{n - 3}+ c \\ =& \frac{2.3}{3}(1.3)^{n - 3} + c \\ >& 0.52(1.3)^n + c \\ >& \frac{1}{2}(1.3)^n + c \end{align} \]

Let us say you want to compute \(P(n) \mod n\) for \(n = 130\). That is still a very small value of \(n\), and yet our formula tells us that this would take approximately 127 years just to compute this one Perrin value!

Dynamic Programming

In particular, to compute \(P(n)\) the algorithm recursively computes \(P(n - 2)\) and \(P(n - 3)\), and these two recursive calls make further recursive calls to compute \(P(n - 4)\), \(P(n - 5)\), \(P(n - 5)\), and \(P(n - 6)\). Note that \(P(n - 5)\) is listed twice.

So if we compute the values in increasing order, remembering the last 3 values in the sequence, we can easily compute the Perrin sequence. The running time is \(\Theta(n)\). But for \(n = 1 \text{ \ billion}\) it still takes 11000 years.

Nasty Algorithm

So how could you possibly do better than linear time?

Well, the fact of the matter is that for any linear recurrence such as Perrin numbers or Fibonacci numbers, you can compute the \(n\)-th value in only \(O(\log n)\) time.

This seems impossible at first, but by incorporating Divide-and-Conquer techniques we can do this.

Review of Matrices and Vectors

We add two \(n \times m\) matrices or two vectors of length \(n\) component-wise.

We multiply two vectors \(X\) and \(Y\) of length \(n\) by taking the following sum \(\sum_{i = 1}^n x_iy_i\).

We multiply an \(n × m\) matrix \(P\) with an \(m × l\) matrix \(Q\) by creating a \(n × l\) matrix \(R = P × Q\) where: \[ R[i, j] = P[i, *] \times Q[*, j] = \sum_{k = 1}^m P[i, k]Q[k, j] \]

Using Matrices/Vectors for Perrin Numbers

\[ \begin{pmatrix} 0 & 1 & 1 \\ 1 & 0 & 0 \\ 0 & 1 & 0 \end{pmatrix} \times \begin{pmatrix} P(n - 1) \\ P(n - 2) \\ P(n - 3) \end{pmatrix} = \begin{pmatrix} P(n) \\ P(n - 1) \\ P(n - 2) \end{pmatrix} \]
