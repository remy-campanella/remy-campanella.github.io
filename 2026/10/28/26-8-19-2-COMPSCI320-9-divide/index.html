Divide-and-conquer Paradigm

Divide-and-conquer.

  • Divide up problem into several subproblems (of the same kind).
  • Solve (conquer) each subproblem recursively.
  • Combine solutions to subproblems into overall solution.

Usage.

  • Divide problem of \(n\) into two subproblems of \(n / 2\). \(O(n)\)
  • Solve recursively.
  • Combine to overall solution. \(O(n)\)

Consequence.

  • Brute: \(\Theta(n^2)\)
  • DC: \(O(n \log n)\)

Mergesort

Sorting Problem

Sorting Problem
Given a list \(L\) of \(n\) elements, rearrange them in ascending order.

Mergesort

  • Sort left half.
  • Sort right half.
  • Merge two haves to make sorted whole.

Merging

  • Scan \(A\) and \(B\) from left to right.
  • Compare \(a_i\) and \(b_j\).
  • If \(a_i \leq b_j\) then append \(a_i\) to \(C\)(no larger than any element in \(B\)).
  • If \(a_i > b_j\) then append \(b_i\) to \(C\)(smaller than any element in \(A\)).

Mergesort Implementation

Input. List \(L\) of \(n\) elements from a totally ordered universe.

Output. The \(n\) elements in ascending order.

\begin{algorithm}
\caption{Merge-Sort}
\begin{algorithmic}
\PROCEDURE{Merge-Sort}{$L$}
    \IF{list $L$ has one element}
        \RETURN $L$
    \ENDIF
    \STATE Divide the list into two halves $A$ and $B$
    \STATE $A \gets$ \CALL{Merge-Sort}{$A$} \COMMENT{$T(n / 2)$}
    \STATE $B \gets$ \CALL{Merge-Sort}{$B$} \COMMENT{$T(n / 2)$}
    \STATE $L \gets$ \CALL{Merge}{$A, B$} \COMMENT{$\Theta(n)$}
    \RETURN $L$
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

A Useful Recurrence Relation

\(T(n)\)
Max number of compares to mergesort a list of length \(n\).

Recurrence. \[ T(n) = \begin{cases} 0 &, n = 1 \\ T(\lfloor \frac{n}{2} \rfloor) + T(\lceil \frac{n}{2} \rceil) + n &, n > 1 \end{cases} \]

Solution. \(T(n) = O(n \log n)\).

Assorted Proofs. We describe serveral ways to solve this recurrence. Initially we assume \(n\) is a power of 2 and replace \(\leq\) with \(=\) in recurrence.

Recursion Tree

Proposition. If \(T(n)\) satisfies the following recurrence, then \(T(n) = n \log n\). \[ T(n) = \begin{cases} 0&, n = 1 \\ 2T(\frac{n}{2}) + n&, n > 1 \end{cases} \]

Pf. [by induction]

  • Base: \(n = 1\), \(T(1) = 0 = n \log_2 n\).
  • Inductive hypothesis: assume \(T(n) = n \log_2 n\).
  • Goal: Show that \(T(2n) = 2n \log_2(2n)\). \[ \begin{align} T(2n) &= 2T(n) + 2n \\ &= 2n \log_2 n + 2n \\ &= 2n(\log_2(2n) - 1) + 2n \\ &= 2n \log_2 2n \end{align} \]

Analysis of Mergesort Recurrence

If \(T(n)\) satisfies the following recurrence, then \(T(n) \leq n \lceil \log_2n \rceil\). \[ T(n) \leq \begin{cases} 0&, n = 1 \\ T(\lfloor \frac{n}{2} \rfloor) + T(\lceil \frac{n}{2}\rceil) + n&, n > 1 \end{cases} \]

Pf. [by strong induction on \(n\)]

  • Base: \(n = 1\).

  • Define \(n_1 = \lfloor n / 2 \rfloor\), \(n_2 = \lceil n / 2 \rceil\), \(n_1 + n_2 = n\).

  • Induction: assume true for \(1, \ldots, n - 1\). \[ \begin{align} T(n) &\leq T(n_1) + T(n_2) + n \\ &\leq n_1 \lceil \log n_1 \rceil + n_2 \lceil \log n_2 \rceil + n \\ &\leq n_1 \lceil \log n_2 \rceil + n_2 \lceil \log n_2 \rceil + n \\ &= n \lceil \log n_2 \rceil + n \end{align} \]

    Claim \[ \log n \leq k = \lceil \log n \rceil \\ n \leq 2^k \\ \frac{n}{2} \leq 2^{k - 1} \\ \lceil \frac{n}{2} \rceil \leq \lceil 2^{k - 1} \rceil = 2^{k - 1} \\ n_2 \leq 2^{\lceil \log n \rceil - 1} \\ \lceil \log n_2 \rceil \leq \lceil \log n \rceil - 1 \]

    So \[ T(n) \leq n \lceil \log n_2 \rceil + n \\ \leq n(\lceil \log n \rceil - 1) + n \\ = n\lceil \log n \rceil \]

Sorting Lower Bound

Theorem. Any deterministic comparison-based sorting algorithm must make \(\Omega(n \log n)\) comparisons in the worst case.

Pf. [information theoretic]

  • Assume the array consists of \(n\) distinct values \(a_1, \ldots, a_n\).
  • Represent the algorithm by a comparison tree. Each internal node is a pairwise comparison, and its two branches represent the possible outcomes for distinct elements.
  • The worst-case number of comparisons is the height \(h\) of the pruned comparison tree.
  • A binary tree of height \(h\) has at most \(2^h\) leaves.
  • There are \(n!\) different orderings. A correct sorting algorithm must distinguish all of them, so the tree has at least \(n!\) reachable leaves.

Therefore, \[ 2^h \geq \text{number of leaves} \geq n! \]

Taking logarithms and applying Stirling’s formula gives \[ h \geq \log_2(n!) \geq n\log_2 n - \frac{n}{\ln 2} = \Omega(n\log n). \]

Thus, every deterministic comparison-based sorting algorithm requires \(\Omega(n \log n)\) comparisons in the worst case.

Note. Lower bound can be extended to include randomized algorithms.

Counting Inversions

Counting Inversions

Music site tries to match your song preferences with others.

Similarity Metric
Number of inversions between two rankings.
  • My rank: \(1, 2, \ldots, n\).
  • Your rank: \(a_1, a_2, \dots, a_n\).
  • Songs \(i\) and \(j\) are inverted if \(i < j\), but \(a_i > a_j\).

Brute force. Check all \(\Theta(n^2)\) pairs.

Divide-and-Conquer

  • Divide: separate list into two halves \(A\) and \(B\).
  • Conquer: recursively count inversions in each list.
  • Combine: count inversions \((a, b)\) with \(a \in A\) and \(b \in B\).
  • Return sum of three counts.

How to Combine Two Subproblems?

Warmup.

  • Sort \(A\) and \(B\).
  • For each \(b \in B\), binary search in \(A\) to find how many elements in \(A\) are greater than \(b\).

Merge-and-count. Count inversions \((a, b)\) with \(a \in A\) and \(b \in B\), assuming \(A\) and \(B\) are sorted.

  • Scan \(A\) and \(B\) from left to right, comparing the current elements \(a_i\) and \(b_j\).
  • If \(a_i < b_j\), then \(a_i\) is not inverted with any element left in \(B\). Append \(a_i\) to the sorted list \(C\) and advance \(i\).
  • If \(a_i > b_j\), then \(b_j\) is inverted with every element left in \(A\). Add \(|A| - i + 1\) to the inversion count (using 1-based indexing), append \(b_j\) to \(C\), and advance \(j\).
  • When either list is exhausted, append the remaining elements of the other list to \(C\) without adding any further cross inversions.
  • Return the cross-inversion count and the merged sorted list \(C\).

Divide-and-Conquer Algorithm Implementation

Input. List \(L\).

Output. Number of inversions in \(L\) and \(L\) in sorted order.

\begin{algorithm}
\caption{Sort-And-Count}
\begin{algorithmic}
\PROCEDURE{Sort-And-Count}{$L$}
    \IF{list $L$ has one element}
        \RETURN $(0, L)$
    \ENDIF
    \STATE Divide the list into two halves $A$ and $B$
    \STATE $(r_A, A) \gets$ \CALL{Sort-And-Count}{$A$} \COMMENT{$T(n / 2)$}
    \STATE $(r_B, B) \gets$ \CALL{Sort-And-Count}{$B$} \COMMENT{$T(n / 2)$}
    \STATE $(r_{AB}, L) \gets$ \CALL{Merge-And-Count}{$A, B$} \COMMENT{$\Theta(n)$}
    \RETURN $(r_A + r_B + r_{AB}, L)$
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

Divide-and-Conquer Algorithm Analysis

Proposition. The sort-and-count algorithm coounts the number of inversions in a permutation of size \(n\) in \(O(n \log n)\) time.

Ramdomized Quicksort

Randomized Quicksort

  • Pick a random pivot \(p \in A\).
  • 3-way partition to \(L\), \(M\), \(R\). \(\forall l \in L, l < p\), \(\forall r \in R, r > p\).
  • Recursively sort \(L\) and \(R\).
\begin{algorithm}
\caption{Randomized-Quicksort}
\begin{algorithmic}
\PROCEDURE{Randomized-Quicksort}{$A$}
    \IF{array $A$ has zero or one element}
        \RETURN
    \ENDIF
    \STATE Pick pivot $p \in A$ uniformly at random
    \STATE $(L, M, R) \gets$ \CALL{Partition-3-Way}{$A, p$} \COMMENT{$\Theta(n)$}
    \STATE \CALL{Randomized-Quicksort}{$L$} \COMMENT{$T(i)$}
    \STATE \CALL{Randomized-Quicksort}{$R$} \COMMENT{$T(n - i - 1)$}
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

Here, \(i = |L|\) is a random variable depending on the pivot \(p\). The annotation \(T(n - i - 1)\) assumes distinct elements, so \(|M| = 1\); in general, \(|R| = n - |L| - |M|\).

Analysis of Randomized Quicksort

Proposition. The expected number of compares to quicksort an array of \(n\) distinct elements \(a_1 < \ldots < a_n\) is \(O(n \log n)\).

Consider BST representation of pivot elements.

  • \(a_i\) and \(a_j\) are compared once iff one is an ancestor of the other.
  • \(P(a_i, a_j \text{ are compared}) = \frac{2}{j - i + 1}, i < j\).
  • Expected number of compares: \[ \sum_{i = 1}^n\sum_{j = i + 1}^n\frac{2}{j - i + 1} = 2\sum_{i = 1}^n\sum_{j = 2}^{n - i + 1}\frac{1}{j} \\ \leq 2n\sum_{j = 1}^n\frac{1}{j} \\ \leq 2n(\ln n + 1) \text{(harmonic sum)} \]

Median and Selection

Selection. Given \(n\) elements from a totally ordered universe, find \(k\)th smallest.

  • \(O(n)\) compares for \(k = 1\) or \(n\).
  • \(O(n \log n)\) compares by sorting.
  • \(O(n \log k)\) compares with a binary heap.

Randomized Quickselect

  • Pick a random pivot \(p \in A\).
  • 3-way partition to \(L\), \(M\), \(R\).
  • Recur in one subarray, the one containing the \(k\)th smallest element.
\begin{algorithm}
\caption{Quick-Select}
\begin{algorithmic}
\PROCEDURE{Quick-Select}{$A, k$}
    \STATE Pick pivot $p \in A$ uniformly at random
    \STATE $(L, M, R) \gets$ \CALL{Partition-3-Way}{$A, p$} \COMMENT{$\Theta(n)$}
    \IF{$k \leq |L|$}
        \RETURN \CALL{Quick-Select}{$L, k$} \COMMENT{$T(i)$}
    \ELIF{$k > |L| + |M|$}
        \RETURN \CALL{Quick-Select}{$R, k - |L| - |M|$} \COMMENT{$T(n - i - 1)$}
    \ELSE
        \RETURN $p$
    \ENDIF
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

Notes. Here, \(1 \leq k \leq |A|\), and \(M\) contains all elements equal to \(p\). The final branch applies when \(|L| < k \leq |L| + |M|\); the lecture’s final condition \(k = |L|\) is a typo. As in quicksort, \(i = |L|\), and the annotation \(T(n - i - 1)\) assumes distinct elements; in general, the right subproblem has size \(n - |L| - |M|\).

Randomized Quickselect Analysis

Intuition. Splitting a candy bar uniformly at random leaves a larger piece whose expected size is \(3/4\) of the whole. This suggests \[ T(n) \leq T(3n / 4) + n \quad \Rightarrow \quad T(n) \leq 4n. \] However, this is not a rigorous recurrence: in general, we cannot assume \(\mathbb{E}[T(i)] \leq T(\mathbb{E}[i])\).

Definitions. Assume distinct elements, as in the lecture analysis.

  • \(T(n, k)\) is the maximum expected number of comparisons needed to select the \(k\)th smallest element in an array of length at most \(n\).
  • \(T(n) = \max_{1 \leq k \leq n} T(n, k)\), with \(T(0) = 0\).
  • The expectation is over the random pivot choices. Since the definition covers arrays of length at most \(n\), \(T(n)\) is monotone non-decreasing.

Proposition. \(T(n) \leq 4n\), under the lecture’s cost model of at most \(n\) comparisons per partition.

Pf. [by strong induction on \(n\)]

Base case. An array of length at most 1 takes at most one comparison, so \(T(1) \leq 1 \leq 4\).

Inductive hypothesis. Assume \(T(j) \leq 4j\) for every \(0 \leq j < n\).

For an array of length \(n\), let \(i\) be the number of elements smaller than the pivot. A uniformly random pivot makes \(i\) uniform over \(0, 1, \ldots, n - 1\). The two outer subarrays have sizes \(i\) and \(n - i - 1\).

Quickselect recurses into at most one subarray. By monotonicity, its recursive cost is at most \(T(\max\{i, n - i - 1\})\). Each possible larger-subarray size occurs at most twice, giving \[ \begin{aligned} \text{expected cost} &\leq n + \frac{1}{n}\sum_{i=0}^{n-1} T(\max\{i, n-i-1\}) \\ &\leq n + \frac{2}{n}\sum_{j=\lfloor n/2 \rfloor}^{n-1} T(j) \\ &\leq n + \frac{8}{n}\sum_{j=\lfloor n/2 \rfloor}^{n-1} j \\ &\leq n + \frac{8}{n}\cdot\frac{3n^2}{8} \\ &= 4n. \end{aligned} \]

The last bound holds for both even and odd \(n\). Arrays shorter than \(n\) are already covered by the inductive hypothesis, so \(T(n) \leq 4n\).

Thus, randomized quickselect uses \(O(n)\) expected comparisons for every valid \(k\).

Selection in Worst-Case Linear Time

Goal. Choose a pivot that guarantees a constant fraction of the elements can be discarded, rather than relying on a random pivot.

Idea. Recursively select the median of a sample of about \(n/5\) elements. A suitable sample guarantees that each outer partition has size at most \(7n/10 + O(1)\).

Ignoring rounding and base cases, the recurrence has the form \[ T(n) \leq T(n/5) + T(7n/10) + O(n). \]

The two recursive subproblems have different sizes, but their sizes sum to only \(9n/10\). The total work is therefore linear; the proof below handles the floor terms explicitly.

Choosing the Pivot Element

  1. Divide the elements into \(\lfloor n/5 \rfloor\) groups of five, plus any leftover elements.
  2. Find the median of each full group. Let \(B\) be the list of these medians.
  3. Recursively select a middle element of \(B\) as the pivot \(p\).
  4. Partition the entire original array around \(p\), including the leftover elements.

The leftovers are ignored only when choosing the pivot, not when selecting the answer.

Median-of-Medians Selection Algorithm

Input. A nonempty array \(A\) and a rank \(1 \leq k \leq |A|\).

Output. The \(k\)th smallest element of \(A\).

\begin{algorithm}
\caption{Mom-Select}
\begin{algorithmic}
\PROCEDURE{Mom-Select}{$A, k$}
    \STATE $n \gets |A|$
    \IF{$n < 50$}
        \RETURN the $k$th smallest element of $A$ via mergesort
    \ENDIF
    \STATE Group $A$ into $\lfloor n/5 \rfloor$ groups of five, ignoring leftovers for this step
    \STATE $B \gets$ the median of each group of five
    \STATE $p \gets$ \CALL{Mom-Select}{$B, \lfloor n/10 \rfloor$} \COMMENT{A middle element of $B$}
    \STATE $(L, M, R) \gets$ \CALL{Partition-3-Way}{$A, p$}
    \IF{$k \leq |L|$}
        \RETURN \CALL{Mom-Select}{$L, k$}
    \ELIF{$k > |L| + |M|$}
        \RETURN \CALL{Mom-Select}{$R, k - |L| - |M|$}
    \ELSE
        \RETURN $p$
    \ENDIF
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

The pivot rank follows the lecture: \(\lfloor n/10 \rfloor = \lfloor |B|/2 \rfloor\). For odd \(|B|\), this is one position below the usual median, but the bounds below still hold.

Why the Pivot Is Good

Let \(q = \lfloor n/10 \rfloor\).

  • At least \(q\) group medians are \(\leq p\). Each such group contributes at least three elements \(\leq p\).
  • At least \(q\) group medians are \(\geq p\). Each such group contributes at least three elements \(\geq p\).
  • Thus, at least \(3q\) elements are \(\leq p\), and at least \(3q\) elements are \(\geq p\).
  • Either recursive outer partition therefore contains at most \(n - 3\lfloor n/10 \rfloor\) elements.

These non-strict inequalities also handle duplicate values: elements equal to \(p\) belong to \(M\) and are excluded from either recursive outer partition.

Analysis of Selection Algorithm Recurrence

Let \(T(n)\) be the maximum number of comparisons on any valid selection input of length at most \(n\). This definition makes \(T(n)\) monotone non-decreasing.

Under the lecture’s comparison model, finding a median of five uses at most six comparisons, and partitioning uses at most \(n\) comparisons. The non-recursive work is at most \[ 6\lfloor n/5 \rfloor + n \leq \frac{11}{5}n. \]

Hence, \[ T(n) \leq \begin{cases} 6n, & n < 50, \\ \max\left\{T(n-1),\ T(\lfloor n/5 \rfloor) + T(n-3\lfloor n/10 \rfloor) + \frac{11}{5}n\right\}, & n \geq 50. \end{cases} \]

The \(T(n-1)\) term covers inputs shorter than \(n\); the other term covers inputs of length exactly \(n\).

Claim. \(T(n) \leq 44n\).

Pf. [by strong induction]

Base case. For \(n < 50\), mergesort gives \(T(n) \leq 6n \leq 44n\).

Inductive hypothesis. Assume \(T(j) \leq 44j\) for all \(j < n\).

Inductive step. For \(n \geq 50\), the first term satisfies \(T(n-1) \leq 44(n-1) \leq 44n\). For the second term, use \(3\lfloor n/10 \rfloor \geq n/4\): \[ \begin{aligned} T(\lfloor n/5 \rfloor) + T(n-3\lfloor n/10 \rfloor) + \frac{11}{5}n &\leq 44\lfloor n/5 \rfloor + 44(n-3\lfloor n/10 \rfloor) + \frac{11}{5}n \\ &\leq \frac{44}{5}n + 44n - 11n + \frac{11}{5}n \\ &= 44n. \end{aligned} \]

Both terms are at most \(44n\), completing the induction.

Conclusion. Median-of-medians selection takes \(O(n)\) time in the worst case, whereas randomized quickselect has an \(O(n)\) expected bound.

Closest Pair of Points

Problem

Given \(n\) points in the plane, find a pair with the smallest Euclidean distance.

  • Brute force. Check all pairs using \(\Theta(n^2)\) distance calculations.
  • 1D version. Sort the points and check adjacent pairs, taking \(O(n \log n)\) time.
  • Non-degeneracy assumption. No two points have the same \(x\)-coordinate, as assumed in the lecture.

First Attempt

Sorting by \(x\)-coordinate and checking nearby positions does not guarantee finding the closest pair in the plane. Sorting by \(y\)-coordinate has the same limitation: the closest points can be separated in either ordering by other points that are far away in the other coordinate.

Second attempt. Divide the plane into four quadrants. This does not guarantee balanced subproblems: a quadrant may contain far more than \(n/4\) points.

Divide and Conquer

  • Divide. Choose a vertical line \(L\) between the middle points in \(x\)-order, producing two subsets whose sizes differ by at most one.
  • Conquer. Recursively find the closest-pair distances \(\delta_1\) and \(\delta_2\) in the left and right subsets.
  • Combine. Let \(\delta = \min\{\delta_1, \delta_2\}\). Search for a cross-boundary pair with distance less than \(\delta\).
  • Return the best of the left, right, and cross-boundary results.

The challenge is to perform the combine step without checking all cross-boundary pairs.

Find Closest Pair

Observation. Any cross-boundary pair closer than \(\delta\) must have both points within distance \(\delta\) of \(L\).

Only points in this \(2\delta\)-wide strip need to be considered. Sort them by \(y\)-coordinate as \(s_1, s_2, \ldots, s_t\).

Claim. It suffices to compare each point with the next seven points in this order. If \(j-i > 7\), the distance between \(s_i\) and \(s_j\) is at least \(\delta\).

Pf.

  • Consider the \(2\delta\)-by-\(\delta\) rectangle in the strip whose bottom edge passes through \(s_i\).
  • Any point above this rectangle differs from \(s_i\) in \(y\)-coordinate by at least \(\delta\), so it cannot be closer than \(\delta\).
  • Split the rectangle along \(L\) and subdivide it into eight squares of side length \(\delta/2\). Each square lies entirely in one recursive half.
  • Each square has diameter \(\delta/\sqrt{2} < \delta\). It contains at most one point, because points in the same half are at least \(\delta\) apart.
  • Thus, the rectangle contains at most eight points, including \(s_i\). At most seven subsequent points can be closer than \(\delta\).

Closest-Pair Algorithm

The following version returns the minimum distance. To return the actual pair, retain the pair attaining each minimum as well. The base case is made explicit here; it is omitted from the lecture pseudocode.

\begin{algorithm}
\caption{Closest-Pair}
\begin{algorithmic}
\PROCEDURE{Closest-Pair}{$P$}
    \STATE $n \gets |P|$
    \IF{$n \leq 3$}
        \RETURN the minimum pairwise distance by brute force, or $\infty$ if $n < 2$
    \ENDIF
    \STATE Choose a vertical line $L$ splitting $P$ into balanced halves $P_L$ and $P_R$
    \STATE $\delta_1 \gets$ \CALL{Closest-Pair}{$P_L$}
    \STATE $\delta_2 \gets$ \CALL{Closest-Pair}{$P_R$}
    \STATE $\delta \gets \min\{\delta_1, \delta_2\}$
    \STATE $S \gets$ points of $P$ within distance $\delta$ of $L$
    \STATE Sort $S$ by $y$-coordinate as $s_1, \ldots, s_t$
    \FOR{$i \gets 1$ \TO $t$}
        \FOR{$j \gets i+1$ \TO $\min\{i+7, t\}$}
            \STATE $d \gets$ \CALL{Distance}{$s_i, s_j$}
            \STATE $\delta \gets \min\{\delta, d\}$
        \ENDFOR
    \ENDFOR
    \RETURN $\delta$
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

The strip and its seven-neighbor bound are formed using the value of \(\delta\) from the two recursive calls. Updating the best distance during the scan does not require rebuilding the strip.

Closest-Pair Analysis

Initial version. Splitting the points by the median \(x\)-coordinate takes \(O(n)\) time using linear-time selection. Sorting the strip by \(y\) at each recursive call costs \(O(n \log n)\), while the seven-neighbor scan costs \(O(n)\).

The resulting recurrence is \[ T(n) \leq T(\lfloor n/2 \rfloor) + T(\lceil n/2 \rceil) + O(n\log n), \] which gives \(T(n) = O(n\log^2 n)\).

Improvement. Avoid sorting the strip from scratch at every call.

  • Sort the full point set by \(x\)-coordinate once, in \(O(n\log n)\) time, so balanced splits are available by position.
  • Each recursive call also returns its points sorted by \(y\)-coordinate.
  • Merge the two sorted \(y\)-lists in \(O(n)\) time, then filter the merged list to obtain the strip in \(y\)-order.
  • Scan at most seven successors per strip point in \(O(n)\) time.

Each combine step is now linear: \[ T(n) \leq T(\lfloor n/2 \rfloor) + T(\lceil n/2 \rceil) + O(n) = O(n\log n). \]

The initial sort also takes \(O(n\log n)\), so the complete algorithm runs in \(O(n\log n)\) time.
