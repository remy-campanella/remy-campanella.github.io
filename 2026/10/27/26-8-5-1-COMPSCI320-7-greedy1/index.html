Coin Changing

Coin Changing

Coin Changing
Given U. S. currency denominations \(\{ 1, 5, 10, 25, 100 \}\), devise a method to pay amount to customer using fewest coins.

Cashier’s Algorithm. At each iteration, add coin of the largest value that does not take us past the amount to be paid.

Cashier’s Algorithm

\begin{algorithm}
\caption{Cashiers-Algorithm}
\begin{algorithmic}
\PROCEDURE{Cashiers-Algorithm}{$x, c_1, c_2, \ldots, c_n$}
    \STATE Sort $n$ coin denominations so that $0 < c_1 < c_2 < \cdots < c_n$
    \STATE $S \gets \emptyset$ \COMMENT{Multiset of coins selected}
    \WHILE{$x > 0$}
        \STATE $k \gets$ largest index such that $c_k \leq x$
        \IF{no such $k$}
            \RETURN no solution
        \ELSE
            \STATE $x \gets x - c_k$
            \STATE $S \gets S \cup \{k\}$
        \ENDIF
    \ENDWHILE
    \RETURN $S$
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

Q. Is cashier’s algorithm optimal for any set of denominations?

A. No. Consider U.S. postage: 1, 10, 21, 34, 70, 100, 350, 1225, 1500. - Cashier’s algorithm: \(140 = 100 + 34 + 1 + 1 + 1 + 1 + 1 + 1\). - Optimal: \(140 = 70 + 70\).

It may not even lead to a feasible solution if \(c_1 > 1\): 7, 8, 9.

  • Cashier’s algorithm: \(15 = 9 + ?\).
  • Optimal: \(15 = 7 + 8\).

Properties of Any Optimal Solution (for U.S. Coin Denominations)

Properties.

  • Number of 1 \(\leq 4\).
  • Number of 5 \(\leq 1\).
  • Number of 5 \(+\) number of 10 \(\leq 2\).

Optimality of Any Optimal Solution (for U.S. Coin Denominations)

Theorem. Cashier’s algorithm is optimal for U.S. coins \(\{ 1, 5, 10, 25, 100 \}\).

Pf.

Consider optimal way to change \(c_k \leq x < c_{k + 1}\): greedy takes coin \(k\).

We claim that any optimal solution must take coin \(k\). If not, it needs enough coins of type \(c_1, \ldots, c_{k - 1}\) to add up to \(x\).

Problem reduces to coin-changing \(x - c_k\) cents, which, by induction, is optimally solved.

Interval Scheduling

Interval Scheduling

Interval Scheduling
Job \(j\) starts at \(s_j\) and finishes at \(f_j\). Two jobs compatible if they don’t overlap. Find maximum subset of mutually compatible jobs.

Greedy Algorithm

Greedy Template. Consider jobs in sone natural order. Take each job provided it’s compatible with the the ones already taken.

Earliest-Finish-Time-First Algorithm

\begin{algorithm}
\caption{Earliest-Finish-Time-First}
\begin{algorithmic}
\PROCEDURE{earliestFinishTimeFirst}{$n, s_1, \ldots, s_n, f_1, \ldots, f_n$}
    \STATE Sort jobs by finish times and renumber so that $f_1 \leq f_2 \leq \cdots \leq f_n$
    \STATE $S \gets \emptyset$ \COMMENT{Set of jobs selected}
    \STATE $t \gets -\infty$ \COMMENT{Finish time of the last selected job}
    \FOR{$j \gets 1$ \TO $n$}
        \IF{$s_j \geq t$}
            \STATE $S \gets S \cup \{j\}$
            \STATE $t \gets f_j$
        \ENDIF
    \ENDFOR
    \RETURN $S$
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

Keep the finish time \(t\) of the last selected job. Since the jobs are sorted by finish time, job \(j\) is compatible with all jobs in \(S\) exactly when \(s_j \geq t\). Initially, \(t = -\infty\), so the first job can always be selected. This implements the compatibility check described on lecture slide 12 (PDF page 13).

  • Sorting: \(O(n \log n)\).
  • Adding: \(O(n)\).

Proposition. Can implement earliest-finish-time first in \(O(n \log n)\) time.

Theorem. The earliest-finish-time-first algorithm is optimal.

Pf. [by contradiction]

Assume greedy is not optimal.

Let \(i_1, i_2, \ldots, i_k\) denote set of jobs selected by greedy.

Let \(j_1, j_2, \ldots, j_m\) denote set of jobs in an optimal solution with \(i_1 = j_1, i_2 = j_2, \ldots, i_r = j_r\) for the largest possible value of \(r\).

By hypothesis, \(i_{r + 1}\) exists and finishes no later than \(j_{r + 1}\).

Replace \(j_{r + 1}\) with \(i_{r + 1}\), the solution is still feasible and optimal, and contradicts the maximality of \(r\).

So the greedy choice is optimal.

Interval Partitioning

Interval Partitioning

  • Lecture \(j\) starts at \(s_j\) and finishes at \(f_j\).
  • Goal: find minimum number of classrooms to schedule all lectures so that no two lectures occur at the same time in the same room

Intervals are open: okay to arrage a class right after a class ends.

Earliest-Start-Time-First Algorithm

\begin{algorithm}
\caption{Earliest-Start-Time-First}
\begin{algorithmic}
\PROCEDURE{earliestStartTimeFirst}{$n, s_1, \ldots, s_n, f_1, \ldots, f_n$}
    \STATE Sort lectures by start times and renumber so that $s_1 \leq s_2 \leq \cdots \leq s_n$
    \STATE $d \gets 0$ \COMMENT{Number of allocated classrooms}
    \FOR{$j \gets 1$ \TO $n$}
        \IF{lecture $j$ is compatible with some classroom}
            \STATE Schedule lecture $j$ in any such classroom $k$
        \ELSE
            \STATE Allocate a new classroom $d + 1$
            \STATE Schedule lecture $j$ in classroom $d + 1$
            \STATE $d \gets d + 1$
        \ENDIF
    \ENDFOR
    \RETURN schedule
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

Proposition. The earliest-start-time-first algorithm can be implemented in \(O(n \log n)\) time.

Lower Bound on Optimal Solution

Depth
The depth of a set of open intervals is the maximum number of intervals that contain any given point.

Observation. Number of classrooms needed \(\geq\) depth. Minimum number of classrooms needed always equal depth.

Analysis

Theorem. Earliest-Start-Time-First algorithm is optimal.

Pf.

Let \(d =\) number of classrooms that the algorithm allocates.

Classroom \(d\) is opened because we needed to schedule a lecture, say \(j\), that is **incampatible with a lecture of \(d - 1\) other classrooms.

Thus, these \(d\) lectures each ends after \(s_j\).

Since we sorted by start time, each of these incompatible lectures start no later than \(s_j\).

Thus, we have \(d\) lectures overlapping at time \(s_j + \epsilon\).

Number of classrooms needed \(\geq\) depth \(\Rightarrow\) all schedules use \(\geq d\) classrooms.

Scheduling to Minimize Lateness

Scheduling to Minimize Lateness

  • Single resoource process one job at a time.
  • Job \(j\) requires \(t_j\) units of processing time and is due at time \(d_j\).
  • If \(j\) starts at time \(s_j\), it finishes at time \(f_j = s_j + t_j\).
  • Lateness: \(l_j = \max{0, f_j - d_j}\).
  • Goal: schedule all jobs to minimize maximum lateness \(L = \max_j l_j\).

Earliest Deadline First

\begin{algorithm}
\caption{Earliest-Deadline-First}
\begin{algorithmic}
\PROCEDURE{earliestDeadlineFirst}{$n, t_1, \ldots, t_n, d_1, \ldots, d_n$}
    \STATE Sort jobs by due times and renumber so that $d_1 \leq d_2 \leq \cdots \leq d_n$
    \STATE $t \gets 0$
    \FOR{$j \gets 1$ \TO $n$}
        \STATE Assign job $j$ to interval $[t, t + t_j]$
        \STATE $s_j \gets t$; $f_j \gets t + t_j$
        \STATE $t \gets t + t_j$
    \ENDFOR
    \RETURN intervals $[s_1, f_1], [s_2, f_2], \ldots, [s_n, f_n]$
\ENDPROCEDURE
\end{algorithmic}
\end{algorithm}

No Idle Time

Observation 1. There exists an optimal schedule with no idle time.

Observation 2. The earliest-deadline-first schedule has no idle time.

Inversions

Inversion
Given an schedule \(S\), an inversion is a pair of jobs \(i\) and \(j\) such that \(i < j\) but \(j\) is scheduled before \(i\).

Observation 3. The earliest-deadline-first schedule is the unique idle-free schedule with no inversions.

Observation 4. If an idle-free schedule has an inversion, then it has an adjacent inversion(two inverted jobs scheduled consecutively).

Pf.

Let \(i-j\) be the closest inversion.

Let \(k\) be element immediately to the right of \(j\).

Case 1. \(j > k\), then \(j-k\) is an adjacent inversion.

Case 2. \(i-k\) is a closer inversion since \(i < j < k\), a contradiction against the “let \(i-j\) be the closest inversion”.

Key Claim. Exchanging two adjacent, inverted jobs \(i\) and \(j\) reduces the number of inversions by 1 and does not increase the max lateness.

Pf.

Let \(l\) be the lateness before the swap, and \(l'\) be it afterwards.

  • \(l'_k = l_k\) for all \(k \neq i, j\).
  • \(l'_i \leq l_i\).
  • If job \(j\) is late,

\[ \begin{aligned} l'_j &=f'_j - d_j \\ &= f_i - d_j \\ &\leq f_i - d_i \\ &\leq l_i \end{aligned} \]

Analysis of Earliest-Deadline-First Algorithm

Theorem. The earliest-deadline-first schedule \(S\) is optimal.

Pf. [by contradiction]

Define \(S^*\) to be an optimal schedule with the fewest inversions.

Can assume \(S^*\) has no idle time.

  • Case 1. \(S^*\) has no inversions. Then \(S = S^*\).
  • Case 2. \(S^*\) has an inversion.
    • Let \(i-j\) be an adjacent inversion.
    • Exchanging jobs \(i\) and \(j\) decreases the number of inversions by 1 without increasing the max lateness.
    • Contradicts “fewest inversions” part of the definition of \(S^*\).

Greedy Analysis Strategies

  • Greedy algorithm stays ahead.
    Show that after each step of the greedy algorithm, its solution is at least as good as any other algorithm’s.

  • Structual.
    Discover a simple “structural” bound asserting that every possible solution must have a certain value. Then show that your algorithm always achieves this bound.

  • Exchange argument.
    Gradually transform any solution to the one found by the greedy algorithm without hurting its quality.

Optimal Caching

Optimal Offline Caching

  • Cache with capacity to store \(k\) items.
  • Sequence of \(m\) item requests \(d_1, d_2, \ldots, d_n\).
  • Cache hit: item in cache when requested.
  • Cache miss: item not in cache when requested.

Goal. Eviction schedule that minimizes the number of evictions.

Optimal Offline Caching: Greedy Algorithms

LIFO/FIFO. Evict item brought in least (most) recently. LRU. Evict item whose most recent access was earliest. LFU. Evict item that was least frequently requested.

Farthest-In-Future(Clairvoyant Algorithm)

Farthest-In-Future(FF)
Evict item in the cache that is not requested until the farthest in the future.

Theorem. FF is optimal eviction schedule.

Reduced Eviction Schedule

Reduced Schedule
A reduced scheduled is a schedule that brings item \(d\) into the cache in step \(j\) only if there is a request for \(d\) in step \(j\) and \(d\) is not in the cache.

Claim. Given any unreduced schedule \(S\), can transform it into a reduced schedule \(S'\) with no more evictions.

Farthest-In-Future: Analysis

Theorem. FF is optimal eviction algorithm.

Invariant. There exists an optimal reduced schedule \(S\) that has the same eviction schedule as \(S_{FF}\) througth the first \(j\) steps.

Caching Perspective

Online Algorithms
Requests are not known in advance.
Offline Algorithms
Full sequence of requests is known as a priori.

Knapsack Problem

The Knapsack Problem

Knapsack Problem
Given \(n\) objects with value \(v_i\) and weights \(w_i\) for \(1 < i < n\) and a knapsack capacity \(W\). What is the maximum value carried in the knapsack?
Rational Knpasack Problem
Objects are allowed to be broken into small pieces. Find \(0 \leq x_i \leq 1\) such that \(\sum_{i = 1}^n = x_iw_i = W\) and maximize \(\sum_{i = 1} x_iv_i\).
0-1 Knapcack Problem
We either take or don’t take each object. Find \(x_i \in \{0, 1\}\) such that \(\sum_{i = 1}^n = x_iw_i \leq W\) and maximize \(\sum_{i = 1} x_iv_i\).

Rational Knapsack

  • Worst case running time is \(O(n \log n)\) to sort by densities then \(O(n)\) to pack knapsack.
  • If few items fill knapsack then a heap data structure may help: \(O(n)\) create, \(O(\log n)\) pop. That is, \(O(n + k \log n)\), where \(k < n\) is the expected number of items.

Proof of Correctness

Theorem. The greedy algorithm that selects items by value/weight densities produces an optimal solution.

Pf.

Assume we label and sort objects such that \[v_1/w_1 \geq v_2/w_2 \geq v_3/w_3 \geq \ldots \geq v_n/w_n\]

If \(\sum_{i = 1}^n w_1 \leq W\) then any algorithm is optimal.

If not, then let \(X = (x_1, x_2, \ldots, x_j, \ldots, x_n) = (1, 1, \ldots, r, 0, 0, \ldots , 0)\) for greedy solution. Where \(0 \leq x_j = r < 1\).

Let \(Y = (y_1, \ldots, y_n)\) for any feasible solution. \(\sum_{i = 1}^n y_iw_i = W, 0 \leq y \leq 1\).

We want to show \(V(X) = \sum_{i = 1}^n x_iv_i \geq \sum_{i = 1}^n y_iv_i = V(Y)\).

Consider \[V(X) - V(Y) = \sum_{i = 1}^n (x_i - y_i)v_i = \sum_{i = 1}^n (x_i - y_i)\frac{w_iv_i}{w_i}\]

Three cases:

  • \(i < j\). Since \(x_i = 1\), \(x_i - y_i \geq 0\) and \(\frac{v_i}{w_i} \geq \frac{v_j}{w_j}\).
  • \(i > j\). Since \(x_i = 0\), \(x_i - y_i \leq 0\) and \(\frac{v_i}{w_i} \leq \frac{v_j}{w_j}\).
  • \(i = j\). \(|x_i - y_i| \leq 1\) and \(\frac{v_i}{w_i} \leq \frac{v_j}{w_j}\).

In all cases \[(x_i - y_i)\frac{v_i}{w_i} \geq (x_i - y_i)\frac{v_j}{w_j}\].

Thus \[ \begin{align} V(X) - V(Y) &\leq \sum_{i = 1}^n \frac{w_iv_j}{w_j} \\ &\leq \frac{v_j}{w_j}\sum_{i = 1}^n (x_i - y_i)w_i \\ &= \frac{v_j}{w_j}(\sum_{i = 1}^n x_iw_i - \sum_{i = 1}^n y_iw_i) \\ &= \frac{v_j}{w_j}(W - W) \\ &= 0 \end{align} \]
