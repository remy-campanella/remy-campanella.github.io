Data Models

Data Repository

The general format of Join is

  • delegate1 specifies the matching key of outer sequence.
  • delegate2 specifies the matching key of inner sequence.
  • delegate3 shows how to construct the new record in the output sequence using the records from the outer and inner sequence.

Agentic API

Traditional APIs

  • Execute predefined business logic.
  • Developer explicitly specifies the workflow.

Agentic Web APIs

  • LLM decides what sctions are needed.
  • Can dynamically invoke tools.
  • Workflow determined at runtime.
flowchart LR

user["User"]
endp["Agent Endpoint"]
llm["LLM"]
db["Tool 1: Database"]
wth["Tool 2: Weather"]
ext["Tool 3: External Tools"]
resp["Final response"]

user --> endp --LLM Request--> llm <--Response Data--> db
llm <--Response Data--> wth
llm <--Response Data--> ext
llm --Compile Final Response--> resp --> user
  • Users: Sends request.
  • Agent Endpoint: Orchestrates execution.
  • LLM: Reasoning, planning and execute by calling tools.
  • Tools: Perform actions, e.g. access DB, web APIs.

LLM

What is LLM?

  • Large language model: a neural network trained to predict the next token.
  • LLM acts as
    • Planner
    • Decisioner
    • Tool selector
    • Response generator
  • LLM is NOT responsible for
    • Database access
    • Business rules
    • Responsibilities remains in tools.

Hosting

Tool

Tool is a function that LLM can invoke.

Principle: LLM thinks, tools carry out the task.

Tool Calling Process

flowchart LR

user["User"]
llm["LLM
Intepret request and plan execution"]
tools["Tools"]
resp["Response"]

user --request--> llm --execution request--> tools --results--> llm --If the results are satisfactory, generate the response.--> resp
llm --If the results are not satis factory, revise the plan.--> tools

Model Context Protocol(MCP)

Overview

A standard way for LLMs to discover and invoke tools.

  • Tool discovery
  • Tool descriptions
  • Tool invocation

Goal: allow LLM applications to use tools consistently.

MCP Architecture

flowchart LR

llm["llm"]
mcpc["MCP Client"]
mcp["MCP Server"]
wt["Weather Tool"]
et["Email Tool"]
pt["Product Tool"]

llm --> mcpc --> mcp --> wt
mcp --> et
mcp --> pt

The LLM does not call endpoints directly.

Metadata

LLM chooses tools using

  • Name
  • Description
  • Parameter schema

Good Tool

  • Performs one task.
  • Clear name.
  • Clear description.

MCP Compliant Tools

In the project folder, install

  • Create a folder called Agentic.
  • Under Agentic, create a folder McpTools.
  • Under McpTools, create CustomerMcpTool.cs.

Register the tools.

  • AddMcpServer: tell the container for hosting the tools.
  • WithHttpTransport: indicate the access to the tools is carried out by HTTP protocol.
  • WithToolsAssembly: find methods with McpServerTool attribute and register them.

Make the tools avaliable on localhost:8080/mcp.
