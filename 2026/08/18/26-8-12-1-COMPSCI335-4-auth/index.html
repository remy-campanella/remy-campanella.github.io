Authentication and Authorization

  • Authentication verifies users’ identities(password, biometric info).
  • Authorization decides whether users have permissions to access resources according to identities.

HTTP Basic Authentication

HTTP provides a challenge and response framework for carrying out authentication.

The server challenges client’s request, then client provides the authentication info.
graph LR

c["client"]
s["server"]
c2["client"]
s2["server"]

c --"GET /home"--> s
s --"401 Unauthorized
WWW-Authenticate: Basic realm=''localhost''"--> c
c2 --"GET /home
Authentication: Basic HkGiCn6886Hj="--> s2
s2 --"200 OK"--> c2

A client accesses an endpoint and the endpoint can only be accessed by authorised user.

If the request does not contain authentication information, the server sends an HTTP response with a 401 status code, and a WWW-Authenticate header.

The format of WWW-Authenticate header for basic authentication is:

  • Basic indicates that the server expects the Basic Authentication
  • realm specifies the resources that are covered by the authentication scheme
  • <our site> could be the URL of the resource

The web client resends the original request with an Authorization header.

The format of the Authorization header id:

<userid>:<password> is encoded in base64 encoding.

The client can send the Authorization header when it makes its original request, and this avoids the challenge and response process.

The operations supported by the Web API (i.e., the methods in the controller class) are:

  • ViewCustomer: Display the information of a user. A user can only view their own information. The user must be authenticated.

Authentication Handler

For methods requires authentication, we need to implement classes that handle authentication.

Different methods might use different mechanisms.

For each mechanisms, we should implement a handler.

  • Create a ./Handler folder.
  • MyAuthHandler.cs carries out authentication for ViewCustomer.
  • AdminHandler.cs processes authentication for ListAllCustomers.

MyAuthHandler and AdminHandler will utilise the datd repository to carry out authentication.

Claim-Based Security

Claim-Based authoritzation is an authorization approach.

  • A “claim” is a statement about the user. It is implemented as a (key, value) pair.
  • A user’s access rights are determined by the claims that user holds.

In ASP.NET core, after a client is successfully authenticated, the client is issued by a ticket. The claims packed in the ticket will be used in subsequent access to the endpoints.

The Structure of a Ticket

Each claim can be regraded as a property that the client has.

A ClaimsIdentity object consists of one or serveral Claim objects.

A ClaimsPrincipal object consists of one or serveral ClaimIdentity objects.

AuthenticationTicket encapsulates the information of the client.

If there isn’t a "Authorization" key, the server will challenge client for this key by returning AuthenticateResult.Fail, that is 401 Unauthorized.

authHeader.Parameter holds a base64 encoded name:password pair. Use Convert.FromBase64String to decode.

Then use _repository.ValidLogin to validate userName and password. If this success, then make Claims and encapsule it into ClaimsIdentity, ClaimsPrincipal, AuthenticationTicket, then return with Success.

If this fails, then return “userName and password do not match”.

AddPolicy() adds a policy to options.
