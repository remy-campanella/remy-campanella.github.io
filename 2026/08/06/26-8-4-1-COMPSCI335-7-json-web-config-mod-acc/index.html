JavaScript Object Notation

JSON Types

  • string: enclosed in double quotation marks.
  • number: any type of number.
  • boolean: true, false.
  • null
  • array: enclosed with [].
  • object
    • one or several <key>: <value> pairs.
    • enclosed with {}.
    • pairs are seperated with ,.
    • <key> is a string, <value> could be any JSON type.

Using ASP.NET Core to Develop WebAPI

There is a DB table Customers that stores the information of customers.

The API provides

  • GetCustomers
  • GetCustomer
  • AddCustomer

To create a WebAPI project, execute

Delete ./WeatherForcast.cs, ./Controllers/WeatherForcastControllers.cs.

Go to project root, i nstall packages.

Our program is a service container. The container hosts a lot of components. The project contains several files that allow the service container to be configured.
graph TB

subgraph sc ["service container"]
direction TB
  c1["component 1"]
  c2["component 2"]
  c3["component 3"]
  ws["web server"]
end

Open ./Properties/launchSettings.json.

applicationUrl tells the service container which port API listens for incoming requests.

Open ./appSettings.json.

Logging specifies the type of information that will be stored in the log of web server. AllowedHosts indicates that which IP address can send request to the web server.

For the service that will be used in the execution of the system, we need to register it first.

The processing of the http request consists of a pipeline.
flowchart LR

req["HTTP Request"]
m1["Middleware 1"]
m2["Middleware 2"]
m3["Middleware 3"]
endp["endpoint"]
resp["HTTP Response"]

req --> m1 --> m2 --> m3 --> endp
m1 --> resp
m2 --> resp
m3 --> resp
endp --> resp

Each middleware (i.e., a component) carries out some operations on the incoming request. After processing a request, a middleware might

  • pass the request to the next middleware in the pipeline or
  • send response back to the client immediately without passing the request down the pipeline.

The endpoint is the code that we write to process the http request that meet the needs of our specific application. It is also called controller.

Open Program.cs.

builder represents the service hosting our applicant.

Service is a collection of objects that provide functionality to other parts of the application. It can be regarded as a registry.

AddControllers registers the services required to support the execution of the endpoints.

  • app: encapsule our application.
  • UseHttpsApplication: redirect HTTP request to HTTPS.
  • UseAuthorization: if the controller’s method indicates that only clients with permission can access a method, it checks the permission of the client
  • MapControllers: map URL to the right endpoints
  • Run: starts the pipeline
flowchart LR

red["redirect"]
auth["authorisation"]
endp["endpoint"]

red --> auth --> endp

When we run the application, the .NET runtime system will decide whether to do an HTTP redirect or not based on we have started the application in development or deployment environment. When we use development system, we don’t need to encrypt the information sent to the server. Then the runtime system will not redirect requests using HTTP protocol. The configuation is done in ./Properties/launchSettings.json.

So the “HTTP redirect” module in the pipline will be ignored in the runtime system in the development environment.

Data Model

The data model represents the data objects stored in the database.

We usually store data models in ./Model folder.

Data Access(DB Context)

The Data Access (DB Context) layer is a bridge between the data storage and the program code. It hides the detailed implementation of the data storage from the program.

You should first install some packages.

Then create DB contexts in ./Model.

We need to register WebAPIDBContext with the service container. So, it knows how to call it.

  • options => options.UseSqlite() tells the service container how to connect to the database.
  • builder.Configuration["WebAPIConnection"] obtains the location and the name of the DB from ./appsettings.json.

So add the pair in ./appsettings.json.
