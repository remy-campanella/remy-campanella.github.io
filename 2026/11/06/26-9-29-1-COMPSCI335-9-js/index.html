JavaScript

JavaScript is a powerful, high-level programming language primarily used to make web pages interactive.

While HTML structures the content and CSS styles it, JavaScript adds behaviour — such as responding to clicks, validating user input, loading content dynamically, and more.

It runs directly in the browser, which makes it essential for client-side web development.

JavaScript alert()

JavaScript alert(message) is a built-in function that displays a popup dialog box with a message and an OK button.

It is good for quick testing and debugging, but not recommended for production websites or serious user interfaces.

  • It can’t be styled or customized (e.g., font, colours, buttons).
  • Modern browsers block alert()s if they are overused or misused.

Strict Mode

Strict mode in JavaScript is a way to opt into a safer, more predictable version of the language.

It helps catch silent errors, prevents dangerous actions, and encourages better practices — making it especially useful for beginners and large codebases.

Console Log

Using console.log() is a better alternative for debugging – it does not interrupt the user experience. The output of console.log() appears in the browser’s developer console.

Developer Console

The browser’s developer console is a tool built into web browsers that lets developers inspect and debug websites.

JavaScript errors, warnings, and logs will appear in the developer console automatically.

The developer console is an important tool in the developers’ tool chest: we can set breakpoints to pause code at certain lines, step through the code line-by-line, and watch variables and expressions.

Variables, Types and Control flow

Variables are declared using the keywords let and const.

  • The keyword let declares a mutable variable.
  • The keyword const declares a binding that cannot be reassigned. An object or array referenced by that binding can still be modified.

JavaScript Data Types

JavaScript is a dynamically typed language, and is not a strongly typed one.

Even if it doesn’t require us to declare types, the language must still understand what kind of data it’s dealing with in order to work properly.

We can check types explicitly using the keyword typeof.

Arrays are objects, so typeof alone cannot identify them.

Type Coercion

Type coercion is JavaScript’s automatic conversion of one data type into another when required.

Type can be converted manually by constructors.

JavaScript Conditional Statements

JavaScript Loose Equality

Loose equality (==) compares two values after type coercion.

Loose inequality (!=) is the opposite of ==, but still allows type coercion.

JavaScript Strict Equality

Strict equality (===) compares two values without type coercion.

Both type and value must match exactly.

Strict inequality (!==) is the opposite of ===, there is no type conversion.

JavaScript Loops

JavaScript try...catch

  • try block runs first.
  • If there is an error, catch block runs.
  • The finally block runs no matter what — even if there’s an error or not — before everything finishes.

JavaScript Objects

We are declaring a constant reference to the object — not making the object itself immutable. The keyword const means we cannot reassign the variable, but we can still change the contents of the object it refers to.

Adding a new property such as address to the person object here therefore is okay. However, assigning person to, for example, {}(i.e., and empty object) is not.

JavaScript Functions

The first function uses the function declaration syntax. The second function uses function expression syntax. The variable functionName2 holds a reference to the function.

Functions defined using the function declaration syntax can be used before they are defined. This is called hoisting: functions defined using the function declaration syntax are hoisted.

Functions defined using the function expression syntax can only be used after they are defined.

Functions could be methods associated with an object.

The example also used interpolated string, allowing us to dynamically build strings in a cleaner and more readable way. Interpolated string use ``.

Lambdas – Arrow Functions

An arrow function is a more concise syntax for writing function expressions.

Rest Parameters

Rest parameters allow us to pass a variable number of parameters to a function.

Classes & Inheritance

Classes

In JavaScript class syntax, instance variables do not use let or const keywords, and methods do not use the function keyword.

Extending the Base Class

Class Fields

Public fields do not need to be declared beforehand. Therefore, if we don’t declare name, JavaScript will just create this.name when we assign it in the constructor.

Private fields, however, must be declared at the top level of the class body before use. If we skip #age; and try to do this.#age = age, this will be an error.

Arrays & Higher-Order Functions

Arrays

An array is a special variable(object) in JavaScript that can hold multiple values in an ordered list. Arrays can hold values of any type(even other arrays).

Higher-Order Functions

A higher-order function is a function that does one or both of the following:

  • Takes another function as a parameter
  • Returns a function as its result

Higher-order functions help us write cleaner, more modular, and reusable code — especially when dealing with things like arrays, callbacks, or event handlers.

Array forEach

The forEach() method is a higher-order function that executes a provided function once for each array element. Its return value is undefined. Values returned by the callback are discarded.

If this print function is used only once, we can simplify it into an arrow function.

Array map

The map() method is a higher-order function that creates a new array populated with the results of calling a provided callback function on every element in the calling array.

The return value is the new array with each element being the result of calling the callback function on the corresponding element of the array on which the map is applied.

Array filter

The filter() method is a higher-order function that creates a shallow copy of a portion of a given array, filtered down to just the elements from the given array that pass the test implemented by the provided function.

Array reduce

The reduce() method is a higher-order function that executes a user-supplied “reducer” callback function on each element of the array, in order, passing in the return value from the calculation on the preceding element.

Array reduceRight

The reduceRight() method is a higher-order function that is similar to reduce() but considers the array from right-to-left (instead of left-to-right).

If reduce or reduceRight has the second parameter, then this is the initial value of the accumulation.

Without an initial value, reduce starts with the leftmost element and reduceRight starts with the rightmost element. The callback begins with the next element in the traversal direction.

For three elements, the callback runs twice without an initial value and three times with one. An empty array returns the supplied initial value, but throws a TypeError if no initial value is supplied.

Method Callback result is used to Method returns
forEach Perform an action for each element undefined
map Produce each output element A new array
filter Decide whether to keep the original element A new array
reduce / reduceRight Update the accumulator The final accumulator

Method Chaining

Method chaining in JavaScript is when we call multiple methods on the same value in a single statement, one after the other, because each method returns a value that allows the next method to be called.

As with anything, over-chaining can make code harder to read if each method is doing too much. Sometimes breaking into named steps improves clarity.

Document Object Model

DOM

The DOM is a tree-like structure that represents all elements on our webpage as objects that JavaScript can access and manipulate.

Each tag in the document is a node in the DOM tree.

JavaScript & DOM

JavaScript uses the DOM to read, modify, add, or remove elements and content (including attributes and styles) on the page.

  • document.getElementById("myId"): returns a single element matching the id myId.
  • document.querySelectorAll(selector): returns a node list of all elements that match the given CSS selector. We can then process each of the nodes.

Reading the DOM

Method Matches by Returns
getElementById id One element, or null
getElementsByClassName Class name An HTMLCollection
getElementsByName name attribute A NodeList
getElementsByTagName Tag name An HTMLCollection
getElementsByTagNameNS Namespace and local name An HTMLCollection
querySelector CSS selector The first match, or null
querySelectorAll CSS selector A NodeList of all matches

Collections may be empty. A collection containing one element still needs indexing, such as elements[0], to obtain that element.

DOM textContent vs. innerText

The textContent returns all text, regardless of visibility or CSS. The innerText returns only the visible text, as rendered by the browser. It excludes hidden elements (display: none). It also takes CSS and layout into account (line breaks, etc.).

Here textContent includes Hello, Secret, Hidden, and World, including whitespace text nodes from the source. For this rendered element, innerText includes Hello and World. Exact whitespace depends on the HTML and layout.

Modifying DOM

When we get an element (i.e., node) we can modify the properties(content, attributes, and style).

Adding to DOM

The document.createElement(localName) method creates the HTML element specified by localName. The appendChild() method adds a node to the end of the list of children of a specified parent node (the body of the document in this example).

Using innerHTML is a quick and easy way to insert HTML. But it is not safe if it includes user input(injection attack).

Removing from DOM

The remove() method removes the node from the DOM. It returns nothing. If we want to use the removed node, then assign it to a variable first(oldPara).

Event Listeners

Registering the listener leaves the heading unchanged. Clicking the second heading calls the callback and changes its colour to red.

The Event Parameter

  • Type of event (event.type, e.g., "click")
  • Target element (event.target)
  • Mouse/keyboard data (e.g., event.clientX, event.key)
  • Timestamp (event.timeStamp)

Input Event

The input event occurs as and when an input element (such as <input> or <textarea>) gets user input. The event can be used to capture (and act upon) input as the user enters it.

DOM Properties and Attributes

Form inputs expose the current input through value. Other attributes can be read and updated with getAttribute and setAttribute.

Custom data-* attributes are accessible through dataset. Hyphenated names become camelCase properties, and the values are strings.

Showing and Hiding a Popup

The slides build a popup from a positioned container and a content div. Click handlers change its display value.

The visibility change occurs when the corresponding click handler runs.

Removing Event Listeners

To remove a listener, retain the same function reference that was passed to addEventListener.

A newly written arrow function creates another function object, even when its body is identical.

Remote Data Access

Events and Promises

An event handler may never run because the user may never trigger the event. A remote request instead represents an operation that is expected to complete successfully or fail.

A Promise represents the eventual completion or failure of an asynchronous operation. Its states are pending, fulfilled, and rejected.

Async Functions

An async function always returns a Promise. A returned ordinary value becomes the fulfilment value of that Promise.

Inside a classic script, place await inside an async function. An async function runs synchronously until its first await. Awaiting suspends that function and allows other code to continue. Its continuation runs asynchronously, including when awaiting an already fulfilled Promise.

Fetch and the Two Awaits

fetch(url) returns a Promise for a Response. Reading its body with text() or json() also returns a Promise.

Expression Value
fetch(url) Promise for a Response
await fetch(url) Response
response.text() Promise for a string
await response.text() String
await response.json() Parsed JSON value

Omitting an await can leave a Promise where the following code expects the response or its data. A network failure can reject fetch, while HTTP errors such as 404 still produce a Response. Check response.ok or response.status.

Content Negotiation

The request’s Accept header asks for a representation. The response’s Content-Type describes the representation actually returned.

response.json() parses JSON text. It requires a valid JSON body. Check what the server returns rather than assuming that sending Accept guarantees the requested format.

POST and Authentication

For a JSON request, serialize the object and describe the request body using Content-Type.

For Basic authentication, encodedCredentials is the Base64 encoding of username:password. Base64 is reversible encoding. HTTPS protects credentials in transit.

Execution Order

On a successful request, the log order is Starting → Attempting → Finished → the first part of the data. Calling download starts it immediately, then its first await returns control to examine.

Fetching Multiple Resources

Promise.all waits for all supplied Promises and preserves their input order in the results.

The first stage obtains Responses. The second obtains their bodies. If an input Promise rejects, Promise.all rejects. Other operations already started can still continue.

Script Location

DOM Creation Time

A script executes when the HTML parser reaches it. If the selected element occurs later in the document, it may still be absent.

Accessing heading.innerText here throws an error. Placing a classic script after the required elements makes those elements available when it executes.

External Scripts and Defer

For an external classic script, defer allows downloading during HTML parsing and delays execution until parsing is complete. Deferred classic scripts execute in document order.

Placement Download Execution
Head, ordinary classic script Parser waits while fetching Before parsing later elements
End of body Starts when parser reaches it After preceding elements exist
Head, external script with defer Alongside HTML parsing After parsing completes

Drag & Drop

Drag Source and Drop Target

Set draggable="true" on a source element. A dragstart handler stores data, and a drop handler reads it. Call preventDefault() during dragover to allow dropping onto the target.

This example removes the original element on drop. Moving it into the target would instead use target.appendChild(element).

SVGs and JavaScript

Inline SVG Interactivity

An inline SVG element can receive event listeners like an HTML element.

Dynamically Creating SVGs

Use createElementNS to create elements in the SVG namespace, then set attributes and attach the elements.

After constructing SVG markup with innerHTML, its elements can also be queried and given listeners. Reassigning innerHTML replaces the old descendants, so listeners attached to those old nodes do not transfer to the replacement nodes. Treat untrusted text as text when building either HTML or SVG.

For a data-driven infographic, fetch the data, work out the coordinates and viewBox, then construct the graphic elements.

Best Practices

  • Enable strict mode in classic scripts.
  • Prefer const, using let when reassignment is required.
  • Use strict equality when coercion is not intended.
  • Use textContent for user-generated text.
  • Use external classic scripts with defer when they depend on the DOM.

Code Reading

For an output question, trace the synchronous statements first, then the asynchronous continuations and event callbacks. Events run when triggered.

For an array chain, write the intermediate array after each call. A callback with a block body needs an explicit return when its result is needed.

For a DOM or fetch question, check when the element exists, which expression is a Promise, which value is awaited, and where external data enters the page.
