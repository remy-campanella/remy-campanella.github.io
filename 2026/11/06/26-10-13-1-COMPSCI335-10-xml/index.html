【COMPSCI 335】 Week 10 XML & XML Schema

发表于2026-11-05|更新于2026-11-05|技术学习COMPSCI 335 Web Programming and Distributed Services

XML Intro

XML (Extensible Markup Language) represents structured data using named elements and attributes. XML and HTML share tag-based syntax. XML requires strict well-formedness, while HTML has its own parsing rules.

A Well-Formed XML Document

  • Every element must have matching start and end tags, or use an empty-element tag such as <entry/>.
  • A document must have a single, unique root element.
  • Element and attribute names are case-sensitive.
  • Elements must be properly nested. (They cannot have structural overlaps.)
  • Special characters must be escaped, or represented by a combination of characters.
  • Attribute values must be in quotes.

Well-Formed vs. Valid

A document is well-formed when it follows XML syntax. It is valid against a grammar when it also satisfies the specified DTD or Schema.

A document may be well-formed but violate the permitted child order, required attributes, or value types.

The tags nest correctly here. Whether this entry is valid depends on the grammar.

XML Grammars

XML grammars describe the structure and content of specific XML documents.

These grammar descriptions are above and beyond being well-formed (i.e. content with begin/end tags, proper nesting of tags, escaping of special characters such as <).

Attributes vs. Child Elements

Child elements can be duplicated while attributes cannot be.

E.g. <entry><phone>53281</phone><phone>53282</phone></entry> is OK while <entry phone="53281" phone="53282">...</ entry> is not.

Child elements can describe structures, but attributes cannot. Therefore an attribute can be transformed into a child element, but not all child elements can be transformed into attributes.

XML DTD

Defining Grammar with DTD

Document Type Definitions are the old way of defining the grammar of XML documents.

Pattern:

  • A*: Zero or more As.
  • A+: One or more As.
  • A?: Zero or one A.

Limitations of DTD

There is no way to further qualify the kind of text that can occur where PCDATA has been specified. Saying it can only contain numbers, for example, is not possible.

XML Schema — Introduction

XML Schema

XML Schema define a modern way to specify a permissible tagging structure for a document. Schemas are XML documents. An XML Schema document must itself be well-formed XML and follow the rules of the XML Schema language.

Simple Elements

These are definitions of elements that do not contain any other elements or attributes.

Other common simple types:

  • xs:boolean
  • xs:time
  • xs:decimal
  • xs:anyType: default type.

Schema Namespace

Each of the elements in the schema has a prefix xs: which is associated with the XML Schema namespace through the declaration, xmlns:xs="http://www.w3.org/2001/XMLSchema", that appears in the schema element.

The prefix xs: or xsd: are used by convention to denote the XML Schema namespace, although any prefix can be used.

Occurrence Indicators

Occurrence indicators are element attributes that say how many instances of an element can appear.

  • minOccurs to specify minimum, default is 1.
  • maxOccurs to specify maximum, default is 1, unbounded means there is no maximum limit.

If minOccurs and maxOccurs are both "0", the element must be absent from the instance document. The error is including that element in the instance.

Restrictions on Values

Restriction derives a more limited type from a base type. Bounds such as minInclusive and maxInclusive include their endpoints.

The values 10000 and 99999 are accepted, while 9999 and 100000 are rejected.

Patterns

A pattern facet constrains the permitted text using XML Schema regular expressions.

This matches three digits, a hyphen, and two uppercase letters, such as 123-NZ.

The language-code exercise accepts two letters, optionally followed by a hyphen and two more letters.

Examples include en, EN, en-NZ, and fr-ca. This checks the shape of a code. Checking membership in the actual list of language codes would require additional restrictions.

Union

A union accepts a value if it belongs to any member type. The slides combine two number-plate formats.

Both AB 1234 and ABC123 satisfy a member pattern. The ? makes the separator optional.

Complex Types

Sequence

A complex type can contain child elements and attributes. A sequence specifies child order.

Each child defaults to exactly one occurrence.

Reversing the two children or omitting one violates this type.

Anonymous Types

When a type is only used once, its definition can appear directly within the element declaration.

Choice

A choice selects one branch per occurrence. With the default occurrence bounds, exactly one of the two children appears.

Either <phone><home/></phone> or <phone><work/></phone> is accepted. An empty phone or one containing both children is rejected.

A repeating choice can select a different branch on every repetition.

This allows zero or more email and phone elements in any order, including email, phone, email. The occurrence bounds belong to the choice group.

Named Groups

A group defines a reusable content model. A choice can select a single email element or an entire postal-address sequence.

Choosing the postal branch requires both street and city in that order.

All

An all group permits its child elements in any order.

Both home–work and work–home are valid. Both children are still required because their minimum occurrences default to 1.

Declaration Permitted child combinations
Default all, default children Both children, in either order
all minOccurs="0", default children Both children in either order, or neither
Default all, each child minOccurs="0" Both, only home, only work, or neither

For the XSD 1.0 all model used in the slides, the members are individual element declarations, each with maximum occurrence 1. The group can occur at most once. Minimum occurrences may be 0 or 1.

Attributes and Content

Attribute Declarations

Attributes are declared inside a complex type, after its content model.

use controls attribute presence.

Value Meaning
optional May be present, the default
required Must be present
prohibited Must be absent

Element counts use minOccurs and maxOccurs. Attribute presence uses use.

Default Values

An optional missing attribute can receive its declared default during schema validation. For an element, a default supplies the value of an existing empty element. It does not make a required element optional.

An attribute’s default is compatible with use="optional", which is also the default use.

Simple Content with Attributes

Text with attributes is described by a complex type with simpleContent.

The content is decimal text, with no child elements. A decimal permits fractional digits. Scientific notation such as 1e3 belongs to types such as xs:float, rather than xs:decimal.

Empty Content

A complex type containing only attribute declarations permits attributes with no element or text content.

A completely empty complex type permits no attributes or content. Such an element can act as a presence marker.

Derivation by Extension

A complex type can extend another type.

An instance needs the inherited value and the added currency. The exchangeRate attribute is optional.

Checking Conformance

Check XML syntax first, then read the grammar’s child order, occurrence bounds, value types, and attribute rules.

The DTD (firstname+, familyname, phone+) requires one or more first names, exactly one family name, and one or more phones, in that order. An empty entry is well-formed XML but violates this DTD.

The earlier Schema phonebook example uses different constraints. All three child declarations inside entryType have minOccurs="0", so an empty entry is allowed there. Its owner attribute is optional, whereas the DTD declares owner as required.

When evaluating an instance, use the specific grammar in the question.

Sources

Course slides, XML & XML Schema, pp. 1–68. DTD conformance appears on pp. 18–28, simple types on pp. 34–48, and complex types and attributes on pp. 50–66.

The conformance checks follow the style of the 2025 paper, Questions 41–44. Current slide coverage also includes groups, attribute defaults, and derivation by extension.

The occurrence and content-model rules can also be checked against the W3C XML Schema Primer.
